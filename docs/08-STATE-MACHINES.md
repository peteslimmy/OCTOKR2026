# 4CORE-OKR State Machines

## Reporting-week operating state (separate from session outcome)

A reporting week has `reporting_state` `NORMAL` or `ORGANIZATION_HOLIDAY`. Its governance session independently has `SCHEDULED`, `HELD` or `SKIPPED` outcome. `SKIPPED` is not a holiday: BU reports and manual summary comments remain mandatory. `ORGANIZATION_HOLIDAY` means the organisation is closed and no weekly BU report is due; report reminders, missing-report zero and non-compliance for non-submission are suppressed, and the week is excluded from quarterly scoring.

```text
NORMAL ── authorised holiday declaration ──> ORGANIZATION_HOLIDAY
ORGANIZATION_HOLIDAY ── controlled audited correction ──> NORMAL
```

Each transition requires an authorised actor, timestamp, selected reporting week(s), reason, confirmation and append-only audit event. Post-lock changes that affect quarterly eligibility must create a new versioned score snapshot and preserve the old one. Do not create `VIRTUAL_PRESENT` attendance rows solely because of an organisation holiday. A quarter with no eligible reporting weeks has quarterly score `N/A`.

## Weekly report

```text
DRAFT
  │
  │ Submit Report
  ▼
SUBMITTED
  │
  │ Tuesday 18:00 WAT
  ▼
CONTENT_LOCKED
  │
  │ Following Tuesday 11:00 WAT
  ▼
FINAL_LOCKED
```

### Illegal transitions

- FINAL_LOCKED → DRAFT: prohibited
- FINAL_LOCKED → SUBMITTED: prohibited
- CONTENT_LOCKED → DRAFT: prohibited
- Content unlocked by ordinary user: prohibited

## Task

```text
UNDEFINED
   ├──→ DONE
   └──→ NOT_DONE
```

After Content Lock for BU Lead:

- UNDEFINED → DONE: allowed
- UNDEFINED → NOT_DONE: allowed
- DONE → NOT_DONE: prohibited
- NOT_DONE → DONE: prohibited

After Final Lock for BU Lead:

- all changes: prohibited

Privileged integrity workflow may change:

- DONE → NOT_DONE
- NOT_DONE → DONE

but only through the governed correction operation.

## Goal

Derived only:

- all active tasks DONE → DONE
- otherwise → NOT_DONE

## Quarter

```text
PLANNED
   │
   │ Quarter starts
   ▼
ACTIVE
   │
   │ Next quarter starts
   ▼
LOCKED
```

The quarter and its ordinary strategy/reporting records remain read-only after the next quarter starts. ADR-032 permits only a separate, authorised late-report score amendment: it does not reopen the quarter. The amendment creates a new versioned quarterly score snapshot while preserving the original zero and prior published score.

## Attendance session and source roster

Session states:

- SCHEDULED
- HELD
- SKIPPED

A HELD or SKIPPED governance-session outcome does not change weekly report deadlines. A separate reporting-week state of ORGANIZATION_HOLIDAY suspends the reporting obligation for that affected week. A held session roster transitions DRAFT → FINALIZED. Active staff default to PRESENT in DRAFT; authorised HR may change statuses before finalisation. FINALIZED is terminal for source roster records: direct edits/deletes are prohibited. SKIPPED is the only non-held OKR outcome. It is an atomic transition that sets the week/session to SKIPPED and all staff in the roster snapshot to VIRTUAL_PRESENT; those rows are generated by the skip action and the outcome is audited. Skipped rows are not individual physical-attendance claims and do not generate absence violations. Skipping affects only the physical session; every BU must manually enter a performance summary, submit its weekly report, and have the report reviewed. There is no CANCELLED OKR state.

## Attendance amendment request

```text
PENDING
  ├──→ APPROVED
  └──→ REJECTED
```

- HR may submit a request at any time after roster finalisation.
- Reason is mandatory; evidence is optional.
- A different authorised Admin or designated HR approver makes the decision; self-approval is prohibited.
- Every decision is audited. A mandatory reviewer reason for rejection is proposed pending separate approval.
- Approval appends an amendment and makes its proposed status the effective status, while the source roster and prior status history remain unchanged.
- Terminal requests are not reopened or edited in place; a further correction requires a new request based on the current effective value.
- Stale proposals and duplicate pending requests are rejected safely.

## Violation

Recommended lifecycle:

- OPEN
- ASSESSED
- PAID or DEDUCTION_RECORDED
- CLOSED

Exact statuses may be extended only through ADR.

## Disbursement request

```text
SUBMITTED
  ↓
UNDER_REVIEW
  ├──→ REJECTED
  └──→ APPROVED
          ↓
       DISBURSED
```

Approval does not equal actual disbursement.

## Integrity correction

```text
SELECT TASK
   ↓
ENTER REASON
   ↓
CONFIRM
   ↓
APPLY / WAIVE
   ↓
AUDIT
```

The task change happens as part of the governed transaction.


### Attendance session outcome transitions
- `SCHEDULED → HELD → FINALIZED`: normal OKR session; roster defaults to PRESENT and HR marks exceptions before finalisation.
- `SCHEDULED → SKIPPED`: permitted user confirms Skip OKR for this week; atomic operation marks all staff `VIRTUAL_PRESENT` and freezes the skipped-week attendance result. The weekly report lifecycle remains active and mandatory for every BU; a manual performance summary is required and reports must be reviewed.
- A finalised or skipped outcome is not silently reversible. An authorised, audited exception workflow is required to correct an erroneous session outcome.
